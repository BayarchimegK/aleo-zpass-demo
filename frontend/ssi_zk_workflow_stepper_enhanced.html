SSI · ZKP · Aleo 워크플로우

프라이버시 보존 성인 인증 시스템

나이를 공개하지 않고 성인 여부만 증명합니다.
4단계 흐름을 클릭하여 각 단계의 상세 내용을 확인하세요.

A
자격증명 발급 (VC Issuance)
신뢰할 수 있는 기관으로부터 Verifiable Credential(VC)을 발급받아 개인 지갑에 등록하는 단계입니다. 이 단계는 최초 1회만 수행합니다.
3 steps
보유자 브라우저/지갑
발급자 UI VC 발급
인증 백엔드 레지스트리
1
VC 발급 요청 → 요청
보유자 ──▶ 발급자 UI
▾
사용자(보유자)가 브라우저 또는 지갑 앱을 통해 신뢰 기관의 발급자 UI에 접속하여 Verifiable Credential 발급을 요청합니다. 이 요청에는 신원 확인을 위한 최소한의 정보가 포함됩니다.
POST /api/vc/issue
{
"holder_did": "did:aleo:1xyz...",
"credential_type": "AgeVerification"
}
DID W3C VC HTTPS
2
서명된 VC 반환 ← 응답
발급자 UI ──▶ 보유자
▾
발급자는 사용자의 나이를 확인한 후, 발급자의 개인키로 서명된 VC를 반환합니다. VC에는 실제 생년월일 대신, 영지식 증명 회로가 사용할 수 있는 암호학적 커밋먼트(commitment)만 포함됩니다.
{
"@context": ["https://www.w3.org/2018/credentials/v1"],
"type": ["VerifiableCredential"],
"credentialSubject": {
"age_commitment": "0x8f3a...",
"is_adult": true
},
"proof": { "type": "Ed25519Signature2020" }
}
🔒 실제 생년월일은 VC에 포함되지 않습니다. 암호학적 커밋먼트만 저장되어, 발급자 서버가 데이터를 보관하지 않아도 검증이 가능합니다.
3
VC 등록 → 등록
발급자 UI ──▶ 인증 백엔드
▾
발급된 VC의 서명(공개키 해시)과 커밋먼트 정보가 인증 백엔드의 레지스트리에 등록됩니다. 이후 인증 단계에서 VC의 유효성을 빠르게 검증하기 위한 인덱스 역할을 합니다.
POST /registry/register
{
"vc_id": "vc-uuid-1234",
"issuer_pubkey_hash": "0xab12...",
"commitment": "0x8f3a...",
"expires_at": "2026-12-31T00:00:00Z"
}
Registry Commitment PubKey
B
인증 (Authentication)
보유자가 VC를 제출하면, 인증 백엔드는 개인정보를 직접 확인하지 않고 서명과 커밋먼트만 검증한 후 단기 JWT를 발급합니다.
2 steps
보유자 브라우저/지갑
인증 백엔드 VC 검증
4
VC 제출 → 요청
보유자 ──▶ 인증 백엔드
▾
보유자는 지갑에 저장된 VC를 인증 백엔드에 제출합니다. 이 단계에서 전송되는 것은 VC 자체(서명, 커밋먼트 포함)뿐이며, 생년월일이나 주민번호 등 실제 개인정보는 전송되지 않습니다.
POST /auth/login
{
"verifiable_credential": {
"vc_id": "vc-uuid-1234",
"issuer_signature": "0xEd25519...",
"age_commitment": "0x8f3a..."
}
}
🛡️ 실제 나이·생년월일은 이 요청에 포함되지 않습니다. 서버는 서명 유효성과 레지스트리 등록 여부만 확인합니다.
5
단기 JWT 발급 ← 응답
인증 백엔드 ──▶ 보유자
▾
VC의 서명이 유효하고 레지스트리에 등록된 것이 확인되면, 인증 백엔드는 단기(short-lived) JWT를 발급합니다. 이 토큰은 만료 시간이 짧아 탈취되더라도 피해를 최소화합니다.
{
"access_token": "eyJhbGci...",
"token_type": "Bearer",
"expires_in": 900, // 15분
"scope": "zkp_age_verify"
}
JWT RS256 15min TTL
C
영지식 증명 생성 (ZKP Generation)
사용자 기기(WASM)에서 실제 나이를 외부에 노출하지 않고, Aleo 영지식 회로를 통해 "성인임을 증명하는 암호 증명서"만 생성합니다.
2 steps
보유자 WASM 실행
Aleo / 증명자 영지식 회로·WASM
6
영지식 증명 생성 요청 → 내부 연산
보유자 기기 ──▶ Aleo WASM
▾
사용자 브라우저 내에서 WASM으로 컴파일된 Aleo 증명자(prover)가 실행됩니다. 입력값은 VC에 포함된 나이 커밋먼트와 사용자의 실제 나이(private input)이며, 이 연산은 기기 외부로 전혀 전송되지 않습니다.
// Aleo Leo 회로 (의사 코드)
function prove_adult(
private age: u8,
private commitment_nonce: field,
public commitment: field
) -> bool {
assert(commit(age, commitment_nonce) == commitment);
assert(age >= 19);
return true;
}
🔐 핵심: age(나이)는 private input으로, 기기 밖으로 절대 전송되지 않습니다. 결과값(proof)만 외부로 전달됩니다.
7
증명 결과 반환 ← 결과
Aleo WASM ──▶ 보유자 기기
▾
Aleo 회로 실행이 완료되면 영지식 증명(proof)이 생성됩니다. 이 proof는 "나이를 공개하지 않고 성인임을 수학적으로 증명"하는 암호학적 증거입니다. 이후 D단계에서 콘텐츠 백엔드로 전달됩니다.
{
"zk_proof": "0x4f8a3c2b1d...", // 증명 데이터
"public_inputs": {
"commitment": "0x8f3a...", // 공개값
"is_adult": true
},
"proof_size_bytes": 192
}
Groth16 Aleo Proof WASM
D
콘텐츠 접근 (Content Access)
보유자가 JWT와 ZKP를 콘텐츠 백엔드에 전달하면, 백엔드는 개인정보를 전혀 보지 않고 암호학적으로 검증한 후 성인/미성년 콘텐츠를 분기하여 제공합니다.
2 steps
보유자 브라우저/지갑
콘텐츠 백엔드 검증자
8
JWT + ZKP 전달 → 요청
보유자 ──▶ 콘텐츠 백엔드
▾
보유자는 B단계에서 받은 JWT와 C단계에서 생성한 ZKP를 함께 콘텐츠 백엔드에 전달합니다. JWT는 인증 세션을, ZKP는 성인 여부를 각각 증명합니다.
GET /content/adult
Authorization: Bearer eyJhbGci...

{
"zk_proof": "0x4f8a3c2b1d...",
"public_commitment": "0x8f3a..."
}
JWT Bearer ZK Proof TLS 1.3
9
접근 허용 / 거부 및 콘텐츠 분기 ← 응답
콘텐츠 백엔드 ──▶ 보유자
▾
콘텐츠 백엔드는 JWT 유효성 + ZKP 암호 검증(verify)을 수행합니다. 검증이 통과되면 성인 콘텐츠를, 실패하면 미성년자 콘텐츠 또는 에러를 반환합니다. 이 모든 과정에서 서버는 사용자의 실제 나이를 전혀 알 수 없습니다.
// 검증 성공 응답
{
"access": "granted",
"content_tier": "adult",
"proof_verified": true,
"session_expires": "2026-05-19T12:15:00Z"
}
✅ 서버는 끝까지 사용자의 실제 나이를 보지 않았습니다. 오직 ZKP의 수학적 유효성만 검증했을 뿐입니다.
